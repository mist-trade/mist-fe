# Institutional Quant Workbench — 设计契约与重构计划

> 仅规划阶段：本计划不修改任何代码、不安装依赖。所有落地动作在用户批准后、进入实施阶段执行。

## 决策记录（已确认）

| 维度 | 决策 | 影响 |
|---|---|---|
| 产品方向 | 研究工作台 + 实盘监控（只读，不下单） | 需补齐盈亏/风险/基准语义色与监控态 |
| 主题 | 时间自动切换深/浅色（含手动覆盖） | 两套色板并重，ECharts 双主题 |
| 涨跌色 | 红涨绿跌（A股惯例） | 沿用 `COLORS.up=#ef5350 / down=#26a69a` |
| 样板页 | 新建 `/dashboard` 概览页 | 不动现有三页，先验证设计系统 |
| UI 基座 | 引入 Ant Design 5 | 实施阶段新增依赖 `antd` `@ant-design/icons` `@ant-design/nextjs-registry` `next-themes` |

## 一、项目审计结论

### 1. 路由形态
**App Router**（Next 16.1.4 / React 19.2.3）。无 `/pages`、无 `_app/_document`。三路由：

| 路由 | 类型 | 说明 |
|---|---|---|
| `/` | Server | `redirect("/k")` |
| `/k` | Client（`KLineLivePage`） | K线直播，手动刷新，最重 |
| `/strategies` | Client（`StrategiesWorkspace` 662行） | 策略/信号/告警/回测（信号命中统计） |
| `/chan-tests` | Server（fs 读快照） + Client | 缠论测试，数据流最干净 |

### 2. 组件库与样式
- **无 antd**。依赖仅 `echarts ^6` `next` `react` `react-dom`。
- 样式：Tailwind v4（PostCSS inline，无 tailwind.config）+ `globals.css` 约600行手写 BEM 类。
- 字体：Geist / Geist Mono（`next/font/google`），但 `body` 又写死 `font-family: Arial`——**字体未生效**。

### 3. ECharts 封装
- 全部集中在 `app/components/k-panel/`。树摇正确：`echarts.use([CandlestickChart, BarChart, CustomChart, ...])` + `CanvasRenderer`。
- 图表类型：`candlestick`、`bar`（成交量）、4个 `custom`（合并K/笔/中枢/分型）。**无 line/area/scatter/heatmap**——未来收益曲线/回撤需要补。
- **无共享 theme、无 `echarts.registerTheme`、无 `next/dynamic`**（KPanel 全量打进首屏 bundle）。
- 交互：tooltip（trigger axis + cross）、双 grid axisPointer link、inside+slider dataZoom、legend 6项。无时间范围切换器、无 `echarts.connect` 多图联动。

### 4. 量化指标/表格/交互（现状）
- **零绩效/风险指标**：无 sharpe/sortino/maxDrawdown/胜率/盈亏比/年化/alpha/beta。`StrategyBacktestRun` 只有 `signalCount`/`matchedSecurityCount`。
- 表格：全部原生 `<table>`，**无排序/筛选/分页/导出/展开**。实体：策略版本/信号/告警/回测信号。
- **不存在**：持仓/仓位/成交/订单/资金曲线/权益曲线/回撤区间/基准对比。这些都属"实盘监控"待扩展范围。

### 5. 业务语义颜色
| 语义 | 现状 | 位置 |
|---|---|---|
| 涨 | `#ef5350` 红 | `chartColors.ts:67` |
| 跌 | `#26a69a` 绿 | `chartColors.ts:68` |
| 顶分型 | `#2196f3` 蓝 | `chartColors.ts:74` |
| 底分型 | `#ff9800` 橙 | `chartColors.ts:75` |
| 有效笔 | `#00bcd4` 青 | `chartColors.ts:8` |
| 中枢完成 | `#00e676` 亮绿 | `chartColors.ts:82` |
| 中枢未完成 | `#ffab00` 琥珀 | `chartColors.ts:84` |
| 盈/亏 | **无** | 待设计 |
| 风险/警告 | 仅 `.field-error #c2410c` | `globals.css` |
| 基准 | **无** | 待设计 |
| 品牌/主色 | `#1f7a8c` 青 | `globals.css`（与图表脱节） |

> 全部硬编码 hex，无 Token 化，深浅色共用一套——**深色模式下辨识度无保障**。

### 6. Server/Client、Hydration、Bundle 风险（按严重度）
1. **深色模式整体失效**：CSS 变量随 `prefers-color-scheme` 翻转，但 `echarts.init` 无 theme、`TOOLTIP_CONFIG` 写死 `color:"#000"`、`.kline-*`/`error.tsx`/chan-tests inline 全是浅色 hex → OS 暗色时背景暗、图表工具栏亮，割裂。
2. **无 `next/dynamic`**：KPanel + echarts/core 进入 `/k`、`/chan-tests` 首屏 bundle。`next/dynamic(()=>import, {ssr:false})` 是最大单项体积收益。
3. **无数据层**：手写 fetch + 手工 race guard，无缓存/去重/重试/SWR。监控场景需要断连重连、延迟感知。
4. **无实时数据**：`/k` 名为 Live 实为手动"刷新K线"按钮；数据全量 `setOption` 替换，无 append/shift 流式能力。
5. **Hydration**：`StatsPanel.tsx:35` 用 `toLocaleString("zh-CN")` 受时区/ICU 影响——监控页上线后会成为真问题。
6. **字体未生效**：`layout.tsx` 注入 Geist 但 `body{font-family:Arial}` 覆盖。
7. **ErrorBoundary 冗余**：`app/k/page.tsx` 套了自定义 `ErrorBoundary`，与 App Router `error.tsx` 重复。
8. **Server Component 未用足**：`/k` `/strategies` 零服务端工作，首屏空白。

## 二、样板页选择

**新建 `/dashboard` 概览页**（不动现有三页）。

理由：集中验证设计系统全部组件（KPI 卡片、绩效图表、状态表格、状态色），失败不影响线上三页，验证通过后再向 `/k` `/strategies` 推广。概览页内容（mock 数据先行，对实盘监控做骨架）：

- 顶部：账户净值 KPI 卡（净值/日收益/累计收益/最大回撤/夏普）— tabular numerals 对齐
- 中部：累计收益曲线 + 基准 + 超额（line + area），下方回撤区间（area 负值）
- 右侧：持仓快照表（antd Table：证券/仓位/盈亏/盈亏%）
- 状态条：数据更新时间 + 时区 + 延迟徽章 + 连接状态（在线/重连中/断连）

## 三、设计系统方案（Institutional Quant Workbench）

### 3.1 设计 Token 架构

单一事实来源（SSOT）= `app/styles/tokens.ts`（TS Token 定义）+ `app/styles/themes.css`（CSS 变量，深浅两套）。三处消费同一变量：
- antd `ConfigProvider` theme token ← TS Token
- Tailwind v4 `@theme inline` ← CSS 变量
- ECharts `registerTheme` ← CSS 变量读取

主题切换：`next-themes`（`attribute="data-theme"`，`defaultTheme="system"`，`enableSystem`）。新增"按时间自动切换"= 自定义 `TimeBasedThemeScript`：在 `07:00–18:00` 强制 light，否则 dark，并可被用户手动覆盖并存 localStorage。

### 3.2 颜色契约

**中性/表面（浅 / 深）**
| Token | Light | Dark | 用途 |
|---|---|---|---|
| `--surface-base` | `#f7f8fa` | `#0e1116` | 页面底 |
| `--surface-raised` | `#ffffff` | `#161b22` | 卡片/面板 |
| `--surface-overlay` | `#ffffff` | `#1c2330` | 浮层/tooltip |
| `--border-subtle` | `#e5e7eb` | `#262d3a` | 分隔线 |
| `--border-strong` | `#cbd3df` | `#3a4456` | 强调边框 |
| `--text-primary` | `#151a24` | `#e6edf3` | 主文本 |
| `--text-secondary` | `#5a6472` | `#9aa7b8` | 次文本 |
| `--text-muted` | `#8b95a5` | `#6b7689` | 辅助/时间戳 |

**业务语义（红涨绿跌，深浅可辨）**
| Token | Light | Dark | 语义 |
|---|---|---|---|
| `--sem-up` | `#ef5350` | `#ff6b6b` | 涨/正收益（A股） |
| `--down` | `#26a69a` | `#2dd4bf` | 跌/负收益 |
| `--sem-profit` | `#ef5350` | `#ff6b6b` | 盈（与涨同语义族） |
| `--sem-loss` | `#26a69a` | `#2dd4bf` | 亏 |
| `--sem-benchmark` | `#6366f1` | `#818cf8` | 基准/对比线（靛蓝，与涨跌正交） |
| `--sem-excess` | `#8b5cf6` | `#a78bfa` | 超额收益（紫，区别于基准） |
| `--sem-risk` | `#f59e0b` | `#fbbf24` | 风险/回撤区间填充 |
| `--sem-warn` | `#f59e0b` | `#fbbf24` | 警告/延迟高 |
| `--sem-danger` | `#dc2626` | `#f87171` | 严重/断连/止损 |
| `--sem-success` | `#16a34a` | `#4ade80` | 成功/确认（与"跌"绿区分：更深饱和） |

> 关键：深色模式对红/绿/橙统一提亮 8–12% 亮度并降饱和，保证 WCAG AA 文本对比（≥4.5:1 on `#0e1116`）。`--sem-success` 故意比 `--down` 更深更饱和，避免"绿=成功"与"绿=跌"在盈亏表格里混淆。

**品牌主色**：保留 `#1f7a8c` 青为 `--brand`，用作非语义强调（选中态/链接），**不**用于涨跌/盈亏。

**缠论结构色**沿用，但 Token 化并配深色变体：有效笔青、顶分型蓝、底分型橙、中枢完成绿/未完成琥珀。

### 3.3 字体
- Sans：**Geist**（已在 `next/font`，删除 `body{font-family:Arial}` 即可生效）。
- Mono/数字：**Geist Mono** 全局数字 `font-variant-numeric: tabular-nums`；KPI/表格数字列强制 `font-feature-settings: "tnum"`，保证小数点/千分位/正负号对齐。
- 正负号：统一规则（正数显 `+`，0 不带色），千分位 `,`，百分比默认 2 位小数，价格按品种精度。

### 3.4 间距 / 圆角 / 阴影 / 密度
- 间距阶 4px：`4/8/12/16/24/32/48`。antd token `marginXXS=4 … marginXLN=48`。
- 圆角：控件 `6px`、卡片 `8px`、大面板 `12px`、图表容器 `0`（数据感）。antd `borderRadius=6`。
- 阴影：克制。仅 `--shadow-card`（浅 `0 1px 2px rgba(0,0,0,.06)` / 深 `0 1px 2px rgba(0,0,0,.4)`）+ `--shadow-overlay`。**禁玻璃拟态、禁大范围渐变、禁霓虹发光**。
- 密度：中高。表格行高 `36px`（紧凑），KPI 卡 padding `16px`，栅格 12 列、gutter `16`，max-width `1440`（沿用现有）。

### 3.5 ECharts 主题契约
新增 `app/components/charts/echarts-theme.ts`：
- `registerTheme("mist-light", ...)` / `registerTheme("mist-dark", ...)`，在 app 初始化时 `echarts.registerTheme` 一次。
- 主题读取 §3.2 CSS 变量值（构建期为常量，运行期由 theme provider 在 init 时传入对应主题名）。
- `useChartRender` 改造：`echarts.init(container, currentTheme)`，监听主题切换 → `dispose + init(theme)` 或 `setOption` 更新受影响项（tooltip/axis 颜色）。
- Tooltip：背景用 `--surface-overlay`，文字 `--text-primary`，OHLC 数字 tabular，涨跌着色（开收比较）。
- axisPointer cross、dataZoom、legend 保留；新增**时间范围切换器**（`1D/1W/1M/3M/1Y/Max`，控制 dataZoom start/end）组件，复用于 dashboard 与未来 /k。
- 新增图表类型（dashboard 需要）：`line`（累计收益）、`line`+area（回撤）、`line`（基准对比）、`bar`（可选月度收益）。注册时 `LineChart` 进 `echarts.use`。
- 数据更新时间戳：Tooltip 头部显示 `数据时间 HH:mm:ss · 时区 · 延迟 Nms`。
- 视觉稳定性：实时更新（未来）走 `setOption` 的 `notMerge:false` + 增量 append，避免全量替换抖动；动效统一 `animationDuration:300, animationEasing:'cubicOut'`，实时流期间设 `animation:false`。

### 3.6 状态系统契约
| 状态 | 组件 | 规则 |
|---|---|---|
| Loading | `KPanelSkeleton`（已存在，接入新色板）+ antd `Skeleton` 用于表格/卡片 | 保留 shimmer，颜色随主题 |
| Empty | 统一 `EmptyState` 组件（图标+文案+可选操作） | 替换散落的"暂无…"字符串 |
| Error | 路由级 `error.tsx`（保留）+ 删除冗余 `ErrorBoundary` | 内联错误用 antd `Alert`，附重试按钮 |
| 断连/延迟 | `ConnectionBadge`（在线/重连中/断连 + 延迟 ms） | 用 `--sem-success/warn/danger`，仅 dashboard 概览先落地 |
| 时区/更新时间 | `DataFreshnessLabel`（数据时间 + 相对时间 + 时区） | 固定 `Intl.DateTimeFormat("zh-CN",{timeZone, hour12:false})` 防 hydration 不一致 |

## 四、分阶段重构计划

每阶段都附**验证方法**。整体顺序：先地基（Token + 主题 + antd 接入）→ 图表主题 → 样板页 → 推广 → 数据层/实时 → 收尾。

### 阶段 0 — 地基：设计 Token + 主题系统 + antd 接入
**做什么**
1. 新增依赖（实施阶段）：`antd@^5` `@ant-design/icons@^5` `@ant-design/nextjs-registry@^5` `next-themes@^0.4`。
2. 新建 `app/styles/tokens.ts`（SSOT）+ `app/styles/themes.css`（深浅 CSS 变量，§3.2 全表）。
3. `app/layout.tsx`：接入 `AntdRegistry` + `next-themes <ThemeProvider>` + antd `ConfigProvider`（token 来自 §3.2）+ `TimeBasedThemeScript`（07–18 light）。删除 `body{font-family:Arial}`，让 Geist 生效。
4. Tailwind `@theme inline` 映射新 CSS 变量。
5. 保留旧 `globals.css`，新 Token 并存（后续阶段逐步迁移）。

**验证**
- `pnpm build` 通过；首屏不报 antd/next-themes hydration 警告。
- 浅/深切换：data-theme 属性变化，antd 组件（放一个临时 `<Button>`）颜色跟随。
- 时间脚本：改系统时间到 20:00 自动 dark、09:00 自动 light；手动覆盖后刷新仍保持。

### 阶段 1 — ECharts 双主题 + Token 化图表色
**做什么**
1. 新建 `app/components/charts/echarts-theme.ts`：`registerTheme("mist-light"|"mist-dark")`，色值取自 Token。
2. 改造 `k-panel/config/chartColors.ts`：`COLORS`/`FENXING_COLORS`/笔/中枢色改为读 Token（提供 light/dark 两份 map，由 theme 决定）。
3. 改造 `chartOptions.ts`：tooltip/axis 文字色用变量，去硬编码 `#000/#ccc`。
4. 改造 `useChartRender.ts`：`echarts.init(container, themeName)`；监听主题切换重建实例。
5. 包一层 `app/components/charts/ChartContainer`：统一尺寸/空态/加载/错误/主题上下文，未来所有图表经此容器。

**验证**
- `/k` `/chan-tests` 切换深浅：图表背景/tooltip/网格线/涨跌色全部跟随，无残留浅色。
- Jest 现有 `k-panel` 测试全绿（如断言了具体 hex，需同步更新测试）。
- 视觉：深色模式下红/绿/橙辨识度肉眼可分；Lighthouse 对比度无 AA 失败。

### 阶段 2 — 样板页 `/dashboard`（设计系统试金石）
**做什么**
1. 新建 `app/dashboard/`：Server `page.tsx`（mock 数据先行）+ Client `DashboardView.tsx`。
2. 组件：`KpiCard`（tabular 数字）、`EquityChart`（line 收益+基准+超额）、`DrawdownChart`（area 回撤）、`PositionsTable`（antd Table，排序/盈亏色）、`ConnectionBadge`、`DataFreshnessLabel`、`RangeSwitcher`。
3. 全部经 `ChartContainer`；KPanel 用 `next/dynamic({ssr:false})` 懒加载（验证体积收益）。
4. 状态：Loading(Skeleton)/Empty(`EmptyState`)/Error(Alert+重试)/断连 全部演示。

**验证**
- `/dashboard` 浅深双模式视觉一致、数字对齐、tooltip 信息完整（含数据时间/时区）。
- `pnpm build` 后查看该路由首屏 JS——确认 echarts 不在首屏（dynamic 生效）。
- 响应式：≥1280 三栏、768–1280 两栏、<768 单栏可读。
- 与设计 Token 对照：无任何硬编码颜色（grep `#` in dashboard/）。

### 阶段 3 — 推广到现有页
**做什么**
1. `/k`：迁移到 antd（toolbar 控件）+ ChartContainer + 新色板；接 `RangeSwitcher`；删冗余 `ErrorBoundary`（用 `error.tsx`）；`next/dynamic` KPanel。
2. `/strategies`：原生 `<table>` → antd `Table`（加排序/筛选/分页）；告警状态用新语义色徽章；662 行拆分为子组件。
3. `/chan-tests`：去 inline hex 改 Token；`StatsPanel` 时间格式改固定 `Intl.DateTimeFormat`（修 hydration 风险）。
4. 清理 `globals.css`：迁移完成后删除被 antd/Tailwind 取代的手写类。

**验证**
- 三页浅深切换正常；现有 Jest 测试同步更新并全绿。
- `/k` 首屏 JS 下降（对比阶段 0 baseline）。
- `pnpm lint` `pnpm test` 全绿。

### 阶段 4 — 数据层 + 实时 + 监控态（为实盘监控铺路）
**做什么**
1. 引入 `swr`（或 react-query）替换手写 fetch：去重/缓存/重试/`revalidate`。`api/client.ts` 保留 envelope 解析，上层包 SWR fetcher。
2. `ConnectionBadge` + SWR `onErrorRetry`：断连重连 + 延迟探测（请求 RTT）。
3. KPanel/EquityChart 增量更新能力：`setOption` 增量 append/shift，实时态关动画保视觉稳定。
4. 数据契约扩展（后端对齐）：持仓/盈亏/资金曲线/基准/回撤接口字段（本阶段前端 mock + 类型定义，后端就绪后接真）。

**验证**
- SWR：同 key 多组件挂载只发一次请求；网络断开→`ConnectionBadge` 断连→恢复→自动重连刷新。
- 实时（mock 推送）：图表 append 无整屏闪烁，数字 tabular 不跳位。
- 错误：接口 5xx → Alert + 重试按钮可恢复。

### 阶段 5 — 收尾与文档
**做什么**
1. 设计 Token / 组件 / 图表主题文档（`docs/design-system.md`）：色板表、Token 对照、深浅规则、图表交互规范。
2. 删除空目录 `app/api/types/`、`app/components/test-statistics-panel/`。
3. 更新 `.env.example`（新增监控相关开关）。
4. ESLint 加规则：禁止在 `app/components` `app/**/page.tsx` 内出现裸 hex 颜色字面量（强制走 Token）。

**验证**
- `pnpm lint` 含新规则通过。
- 文档评审：新成员可据此直接产出符合设计系统的页面。
- 全量 `pnpm build && pnpm test && pnpm lint` 绿。

## 五、贯穿全程的约束（设计契约红线）
1. 禁赛博朋克/霓虹/玻璃拟态/装饰动画/大范围渐变；动效 ≤300ms、cubicOut、实时流关动画。
2. 涨跌色恒为红涨绿跌，且**不**与 success/danger 语义混用（success 用更深绿 `--sem-success`）。
3. 基准/超额用靛蓝/紫，正交于涨跌色族，避免双色图表歧义。
4. 所有数字 tabular-nums；正数带 `+`；千分位；价格按品种精度。
5. 任何新颜色必须经 Token，不得裸 hex 进组件。
6. 深浅双主题必须同等设计完整度，图表在深色下辨识度优先（提亮+降饱和+AA 对比）。
7. 时间一律固定时区格式化，杜绝 `toLocaleString` 跨端不一致。
